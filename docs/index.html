What it does

every ~60s every ~15s ───────────── ────────── scan pools → manage open LPs filter + score ↓ vet token claim / reclaim / exit size + open LP ↓ record PnL in SQLite

Scan & vet

Finds hot SOL-quoted Meteora pools and skips obvious rugs.

Open LP

One-sided SOL bid-ask below price (meme/micro) or spot (majors).

Manage

Mechanical exits — stop, safety, above/below range, escape.

Paper simulates fills against live pool data. Live uses your burner wallet. Same brain, two locks for live.

Install & run (paper)

Do these in order. Stay in paper until you’re comfortable.

  1. Download the repo

    git clone https://github.com/CryptoGnome/meteora-farmer.git
cd meteora-farmer

  2. Install packages

    npm install

    Wait until it finishes. A message about better-sqlite3 compiling is normal.

  3. Create your .env file

    cp .env.example .env

    Open .env in a text editor. For paper, keep it simple:

    FARMER_MODE=paper
RPC_URL=https://api.mainnet-beta.solana.com

    Never commit .env. Never paste keys into chat or screenshots. Never use your main wallet for this bot.

  4. Force paper in config.toml

    Open config.toml, find [exec], set:

    [exec]
mode = "paper"

    Live only runs when both config.toml and .env say live. One alone is not enough.

  5. Smoke test (optional)

    npm run scan
npm run vet -- PASTE_A_TOKEN_MINT_HERE

  6. Start paper trading

    npm run run

    Leave that window open. In a second terminal (same folder):

    npm run status

  7. Stop

    npm run halt

    Or press Ctrl+C in the run window (fine for paper).

Commands you’ll use

npm run scan                 # pools that pass gates right now
npm run vet -- <mint>        # full vet report for one token
npm run run                  # start the bot loop
npm run status               # open positions + profit
npm run halt                 # close all + stop
npm run force-close -- <id>  # force-close one position
npm test                     # run tests

Optional dashboard

Local web UI for positions, activity, and settings.

  1. Add a secret to .env

    DASH_TOKEN=pick-a-long-random-password
DASH_PORT=8787

  2. Build once, then start

    npm run dash:build
npm run dash

  3. Open the UI

    Go to http://localhost:8787 and enter the same DASH_TOKEN. On your LAN: http://YOUR_PC_IP:8787.

Going live

Live spends real SOL. Use a burner funded only with money you can lose completely.

  • Paper ran cleanly for a while
  • Fresh burner wallet (not your main)
  • Private RPC URL
  • Jupiter API key
  • Private key in .env (or keypair path)
  • config.toml → mode = "live"
  • .env → FARMER_MODE=live
  • Only one farmer process on that wallet

Private key, RPC, Jupiter

Burner wallet — Phantom (easiest)

  1. Install Phantom.
  2. Create a new wallet / account — not your life savings.
  3. Send only the SOL you’re willing to lose.
  4. Export key: Settings → Security & Privacy → Export Private Key → copy the long base58 string.
  5. Paste into .env:
WALLET_PRIVATE_KEY=paste_the_key_here_with_no_quotes_no_spaces

Close the export screen. Don’t screenshot it. Don’t share it.

Or Solana CLI keypair

solana-keygen new --outfile ./burner.json
WALLET_KEYPAIR_PATH=./burner.json

If both key fields are set, WALLET_PRIVATE_KEY wins.

Private RPC

Public RPC is fine for a paper smoke test. Live needs a private endpoint (e.g. Helius, QuickNode). 

RPC_URL=https://your-provider-url-here
RPC_URL_FALLBACK=https://optional-backup-url

Jupiter API key

Needed for live swaps / zap-out. Create one at portal.jup.ag.

JUPITER_API_KEY=your_key_here

Optional Telegram alerts

  1. @BotFather → /newbot → copy token
  2. @userinfobot → copy chat id
  3. Message your bot once, then:
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=987654321

Flip both live switches

# .env
FARMER_MODE=live
RPC_URL=https://your-private-rpc
JUPITER_API_KEY=your_key
WALLET_PRIVATE_KEY=your_burner_key
# config.toml
[exec]
mode = "live"
npm run run

Keep it running (PM2)

Only after npm run run works by hand.

npm install -g pm2
pm2 start deploy/ecosystem.config.cjs --only meteora-farmer
pm2 save
pm2 logs meteora-farmer

Same file can also start meteora-dash (dashboard) and meteora-deploy (auto-pull).

Troubleshooting

SymptomFix
node -v too old Install Node 20+, reopen the terminal
better-sqlite3 build fail Windows: VS Build Tools (C++). Linux: build-essential
RPC errors Put a private RPC in RPC_URL
Already running / lock No other run open? Only if sure: npm run release
Dashboard unauthorized Set DASH_TOKEN, dash:build, dash, same token in browser
Thought paper, it traded Check both [exec].mode and FARMER_MODE
