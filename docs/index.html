What it does

every ~60s every ~15s ───────────── ────────── scan pools → manage open LPs filter + score ↓ vet token claim / reclaim / exit size + open LP ↓ record PnL in SQLite

Scan & vet

Finds hot SOL-quoted Meteora pools and skips obvious rugs.

Open LP

One-sided SOL bid-ask below price (meme/micro) or spot (majors).

Manage

Mechanical exits — stop, safety, above/below range, escape.

Paper fakes fills. Live uses your burner. Live needs two switches on purpose (env + config).

Why Railway (for most people)

You click deploy, set a few secrets, and get a public HTTPS link for the dashboard. Railway restarts crashes and can redeploy when GitHub updates — that’s the “PM2 + auto-update” story without owning a server.

Already comfortable with a VPS, PM2, or running on your PC? Use the Advanced setup guide instead.

Deploy on Railway (paper)

Do these in order. Stay on paper until you’re comfortable.

  1. Create a Railway account

    Go to railway.com, sign up (GitHub login is easiest). New accounts usually get trial credits.

  2. New project from this GitHub repo

    New Project → Deploy from GitHub → pick CryptoGnome/meteora-farmer (or your fork).

    If the repo is private, grant Railway access to it (or fork to your account first).

  3. Add two services in the same project

    Same repo, two start commands:

    ServiceStart commandPublic?
    farmer npm run run No (private)
    dash npm run dash:build && npm run dash Yes — generate a public domain

    Both need Node 20+. On first deploy, Railway runs npm install for you.

  4. Set shared variables (paper-safe)

    Project → Variables (or each service). Start with:

    FARMER_MODE=paper
RPC_URL=https://api.mainnet-beta.solana.com
DASH_TOKEN=pick-a-long-random-password
DASH_PORT=8787

    Leave WALLET_PRIVATE_KEY empty for paper. As long as FARMER_MODE=paper, it will not live-trade even if config says live.

    Never paste keys into Discord or screenshots. Never use your main wallet.

  5. Attach a volume (important)

    SQLite lives under data/. Without a volume, redeploys can wipe history.

    On the farmer service: add a volume mounted at /app/data (or whatever Railway shows as the app root + /data). Point both services at the same volume if they share the DB; otherwise keep dash read-only against the farmer’s data path as you refine the template.

    Hobby plan (or trial credits) is the realistic floor for always-on + a volume. Free-tier credit alone is usually too small for 24/7.

  6. Deploy

    Click deploy / wait for both services to go green. Open the dash service → Settings → Networking → Generate domain.

Open the dashboard

Use the public HTTPS URL Railway gave the dash service (something like https://….up.railway.app).

Enter the same DASH_TOKEN you set in variables.

That URL works from your phone or any network — no port forwarding. Anyone with the link still needs the token.

Auto-updates

Connect the Railway project to GitHub so pushes to master redeploy. That’s the cloud version of PM2 + meteora-deploy on a home server.

  • Paper: auto-deploy on push is fine.
  • Live: prefer deploying only after CI is green, or click Deploy manually when you mean it.

Keys & APIs (when you’re ready)

Burner wallet — Phantom

  1. Install Phantom.
  2. Create a new account — not your life savings.
  3. Send only SOL you’re willing to lose.
  4. Settings → Security & Privacy → Export Private Key → copy base58.
  5. Paste into Railway variables as WALLET_PRIVATE_KEY (no quotes).

Close the export screen. Don’t screenshot it.

Private RPC

Public RPC is ok for a short paper smoke test. Live needs a private endpoint (Helius, QuickNode, etc.). 

RPC_URL=https://your-provider-url-here

Jupiter API key

For live swaps / zap-out: portal.jup.ag

JUPITER_API_KEY=your_key_here

Optional Telegram

TELEGRAM_BOT_TOKEN=…
TELEGRAM_CHAT_ID=…

Going live

Real SOL. Burner only. One farmer process per wallet.

  • Paper looked sane for a while
  • Burner key + private RPC + Jupiter key in Railway variables
  • Railway: FARMER_MODE=live
  • Config: set [exec] mode = "live" (edit in a fork, or use the dashboard Settings once the dash can write config)
  • Redeploy / restart so both switches are live

Live requires both FARMER_MODE=live and config.toml mode = "live". One alone stays safe.

What it costs

Railway: trial credits to start, then a small monthly floor (often Hobby ~$5) plus usage. Always-on + a volume usually won’t stay on the tiny Free credit alone. Check railway.com/pricing.

Running on your own PC or VPS can be cheaper — see Advanced setup.
